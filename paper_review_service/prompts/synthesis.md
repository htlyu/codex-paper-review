当前阶段是 `synthesis`。你负责综合中立摘要、文献背景、逐项问答和独立 countercheck，生成作者可采取行动的最终报告。输出必须遵循给定 **Report schema**，不是 StageResult；不得添加 stage、analysis、findings 或评分字段。

首先核对论文和各阶段记录，理解核心主张、证据、已被消除的疑问、保留问题及真实覆盖。上游说法有冲突时查实际论文或已核验来源。本阶段允许为既有结论核验公开来源，但不发起新的问题调查，也不得生成未经 countercheck 的新 Issue。

最终 issues 只能从 countercheck 的保留 findings 中逐字段原样选择和排序：ID、措辞、证据、范围、状态和所有其他字段都必须与保留项完全相同，不得润色、合并后改写、重新编号或采用已 remove 的候选。若再次核对发现依据不成立，可省去该项并在 limitations 说明处置，但不能自行生成修订版。不能把未保留候选藏进 summary、strengths 或 coverage 继续作为批评传播。

按 Report 的字段生成结果：

- `summary`：准确概括研究目标、方法、主要贡献与当前证据范围，并说明本轮检查重点。不要使用录用判断、质量分数或无依据的赞誉。
- `strengths`：仅记录论文和调查材料确实支持的优点，注明必要物理页和条件。可为空，不必与问题数量对称；作者自述的新颖性不自动算外部验证的优势。
- `issues`：优先排列影响核心主张的问题。重复根因应已由 countercheck 处理；仍重复时可选择其中一个完整保留项，不能跨条拼合字段或丢失独立限制。逐字段复制选定的 Issue，包括真实证据、影响、反证与下一步行动，不增加 schema 之外的字段。
- `coverage`：至少逐项交代全文主张、相关文献、方法、实验统计、图表视觉检查；状态使用 `checked/partial/not_checked/not_applicable`。根据各阶段实际完成情况填写 details，领域叙事不等于全文技术检查，读过页面也不等于其中每项论证都深查过。
- `reviewed_pages`：合并各阶段与本次调用真实阅读检查过的物理页，去重排序。`visual_pages` 同理，只合并有实际图像查看记录的页，且必须属于 reviewed_pages。`unreviewed_pages` 是所有 PDF 物理页减去 reviewed_pages；两者不得重叠，必须恰好覆盖全篇。不要把报告页数、印刷页码或期望覆盖当作实际记录。
- `sources`：保留实际支持报告判断和必要背景的已核验来源并按 URL 去重；每个 issues.source_urls 都有对应 Source。处理版本或日期冲突时以核验记录为准，无法厘清则缩小判断并在 limitations 说明。不要把“可能相关但尚未打开”的文献列为确定依据。
- `limitations`：明确未完成的阶段、无法获得的关键材料、检索截止与覆盖、不可核验的来源、未检查的页面/图像及任何工作降级。没有发现问题时明确这仅是本轮未检出，不能证明论文无错误。

提交 JSON 前检查：问题 ID 是否全部来自 countercheck 保留集合；引用是否对应正确物理页并保持连续原文；视觉依据是否有真实查看记录；sources 是否覆盖每个外部依据；已读与未读页是否完整分割全篇；是否误把调查未完成写成论文失败。不要为了让报告看起来完整而捏造证据、覆盖或优点。
